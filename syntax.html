Offset Reset Reset Consumer Offset (Emergency Replay or Skip Poison Pill)
Rewinds all partitions to earliest offset to replay data, or shift by +1 to bypass a fatal crash loop. 
# Step 1: Dry-run check new positions without committing
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --group fraud-detection-group --reset-offsets \
  --topic bank-transactions --to-earliest --dry-run

# Step 2: Execute commit (Consumer group must be inactive / stopped!)
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --group fraud-detection-group --reset-offsets \
  --topic bank-transactions --to-earliest --execute

Spring Boot Resilient Producer with Callbacks & Tracing
Publishes events keyed by accountId for partition ordering and logs confirmation asynchronously. 
@Service
public class PaymentProducer {
  @Autowired
  private KafkaTemplate<String, PaymentEvent> kafkaTemplate;

  public void sendPayment(PaymentEvent event) {
    ProducerRecord<String, PaymentEvent> record = new ProducerRecord<>(
      "bank-transactions", event.getAccountId(), event
    );
    record.headers().add("traceId", UUID.randomUUID().toString().getBytes());

    kafkaTemplate.send(record).whenComplete((result, ex) -> {
      if (ex == null) {
        RecordMetadata meta = result.getRecordMetadata();
        System.out.println("Partition: " + meta.partition() + " Offset: " + meta.offset());
      } else {
        System.err.println("Failed to publish: " + ex.getMessage());
      }
    });
  }
}
Spring Boot Consumer with Concurrency & Manual Commit (Ack)
Processes incoming transactions across partitions with manual offset commit to prevent message loss. 
@Component
public class LedgerConsumer {

  @KafkaListener(
    topics = "bank-transactions",
    groupId = "banking-core-ledger",
    concurrency = "3" // Matches 3 partitions
  )
  public void consume(ConsumerRecord<String, PaymentEvent> record, Acknowledgment ack) {
    try {
      processLedgerEntry(record.key(), record.value());
      ack.acknowledge(); // Safe commit after processing
    } catch (Exception e) {
      // Route to Dead Letter Queue (DLQ)
      throw new RuntimeException("Failed processing, routing to DLQ", e);
    }
  }
}
DLQ Handler Dead Letter Publishing Error Handler (Poison Pill Guard)
Automatically routes failing or unparseable messages to .DLT topic after 3 exponential retries. 
@Bean
public DefaultErrorHandler errorHandler(KafkaTemplate<Object, Object> template) {
  // Forwards bad events to <topic>.DLT with original exception headers
  DeadLetterPublishingRecoverer recoverer = new DeadLetterPublishingRecoverer(template);
  FixedBackOff backOff = new FixedBackOff(1000L, 3); // 3 retries, 1s interval
  return new DefaultErrorHandler(recoverer, backOff);
}
confluent-kafka Production Python Producer with Delivery Report
Fast C-based Kafka client with idempotence, compression, and delivery receipt confirmation. 
from confluent_kafka import Producer
import json

def delivery_report(err, msg):
    if err is not None:
        print(f"❌ Publish failed: {err}")
    else:
        print(f"✅ Tx committed to {msg.topic()} [P-{msg.partition()}] offset={msg.offset()}")

producer = Producer({
    'bootstrap.servers': 'localhost:9092',
    'acks': 'all',
    'enable.idempotence': True,
    'compression.type': 'snappy'
})

producer.produce(
    topic='bank-transactions',
    key='ACC-101'.encode('utf-8'),
    value=json.dumps({"amount": 250, "type": "TRANSFER"}).encode('utf-8'),
    on_delivery=delivery_report
)
producer.flush()
confluent-kafka Resilient Python Consumer with Manual Sync Commit
Safely polls messages and commits offsets synchronously only after processing completes. 
from confluent_kafka import Consumer, KafkaError
import json

consumer = Consumer({
    'bootstrap.servers': 'localhost:9092',
    'group.id': 'fraud-detection-py',
    'auto.offset.reset': 'earliest',
    'enable.auto.commit': False # Explicit manual commit
})

consumer.subscribe(['bank-transactions'])

try:
    while True:
        msg = consumer.poll(timeout=1.0)
        if msg is None: continue
        if msg.error():
            print(f"Consumer error: {msg.error()}")
            continue

        data = json.loads(msg.value().decode('utf-8'))
        print(f"Processed account {msg.key().decode()}: {data}")
        consumer.commit(msg, asynchronous=False) # Safe commit
finally:
    consumer.close()
KafkaJS Node.js KafkaJS Producer (Idempotent)
Publishes message batches with key-based partition affinity using KafkaJS. 
const { Kafka, CompressionTypes } = require('kafkajs');

const kafka = new Kafka({
  clientId: 'payment-gateway-node',
  brokers: ['localhost:9092']
});

const producer = kafka.producer({ idempotent: true });

async function sendTransaction() {
  await producer.connect();
  await producer.send({
    topic: 'bank-transactions',
    compression: CompressionTypes.GZIP,
    messages: [
      {
        key: 'ACC-101', // Ensures same partition
        value: JSON.stringify({ amount: 500, type: 'DEPOSIT' }),
        headers: { correlationId: 'tx-uuid-889' }
      }
    ]
  });
  console.log('Transaction dispatched!');
}
sendTransaction();
KafkaJS Node.js KafkaJS Consumer (eachMessage)
Subscribes to topic and processes events with automatic partition rebalance handling. 
const consumer = kafka.consumer({ groupId: 'notifications-service' });

async function startConsumer() {
  await consumer.connect();
  await consumer.subscribe({ topic: 'bank-transactions', fromBeginning: true });

  await consumer.run({
    eachMessage: async ({ topic, partition, message }) => {
      const key = message.key.toString();
      const payload = JSON.parse(message.value.toString());
      console.log(`[P-${partition}] Offset: ${message.offset} Key: ${key}`, payload);
    },
  });
}
startConsumer();
Producer Financial Durability & Zero Data Loss Config
Guarantees zero duplicate messages, strict ordering, and multi-broker write acknowledgment. 
# Guarantees all In-Sync Replicas persist message
acks=all
enable.idempotence=true
retries=2147483647 # Retry indefinitely
max.in.flight.requests.per.connection=5

Broker / Topic Replication Barrier (min.insync.replicas)
Requires minimum active replicas before acknowledging produce requests when acks=all. 
# Topic-level config (Minimum 2 replicas must write)
min.insync.replicas=2

# If cluster has 3 brokers, 1 broker can fail without downtime.
# If 2 brokers fail, producers get NotEnoughReplicasException.
Consumer Offset Reset Strategy (earliest vs latest)
Determines where a new consumer group starts when no previous committed offset exists. 
# Read all historical messages from beginning of topic
auto.offset.reset=earliest

# Or only process newly arriving events after connection
auto.offset.reset=latest

# Disable auto-commit for zero-loss manual acknowledgment
enable.auto.commit=false
🔑
Partition Key Formula: Strict Chronological Ordering
When publishing, Kafka calculates MurmurHash2(key) % num_partitions. Because the mathematical hash for an account ID (e.g. ACC-101) never changes, every credit, debit, and transfer for that specific customer always arrives in the exact same partition in unbroken sequence.
📑
Sequential Offsets & High Watermark (HW)
Offsets are 64-bit monotonically increasing integers. The High Watermark (HW) represents the latest offset successfully replicated across all In-Sync Replicas. Consumers are only permitted to read up to the HW to prevent reading uncommitted, phantom data.
👥
Consumer Groups & 1-to-Many Independent Read Offsets
Each Consumer Group maintains its own cursor pointer in __consumer_offsets. Group A (Core Ledger) can be at offset 1000, while Group B (Fraud ML) is at offset 1000, and Group C (Audit Archive) is back at offset 200 replaying history without affecting other consumers!
☠️
Poison Pills & Dead Letter Queues (DLQ)
A "Poison Pill" is a corrupted payload that causes a consumer to throw an unhandled deserialization exception. Without a Dead Letter Queue (DLQ), the consumer crashes, restarts, polls the exact same offset, and enters an infinite crash loop, halting the partition.
